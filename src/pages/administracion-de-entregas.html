Estrategias de Despliegue

"Willie nunca lanzaba un álbum sin probarlo primero con el público en conciertos pequeños. Eso es el Canary Release."

Dos ambientes idénticos. El tráfico se redirige instantáneamente. Como pasar del Lado A al Lado B del LP: el público no nota el cambio.

Deploy gradual: 5%→50%→100%. Como Willie tocando en el Hunts Point Palace antes del Madison Square Garden.

✓ Sin downtime · Eficiente✗ Rollback más complejo

13 — Conclusiones

Hallazgos Clave

🥁
La automatización es imperativa. Como Colón automatizando los arreglos — los pipelines CI/CD eliminan el error humano y aceleran el time-to-market en un ~75%.
🎺
Releases pequeñas y frecuentes son más seguras. Como lanzar singles antes del álbum — menor riesgo, feedback inmediato, rollback simple.
🎸
Separar deploy de release agrega valor. El trombón ensaya (deploy) antes de que el público lo escuche (release). Feature Flags son el control maestro del volumen.
🎵
La observabilidad no es opcional. Sin oído absoluto — logs, métricas y trazas — no puedes dirigir la orquesta en producción.
🌟
La cultura importa tanto como la tecnología. Willie Colón unió el Bronx con Latinoamérica a través de la música. DevOps une Dev y Ops. Organizaciones élite: 208× más deploys, 2,604× mejor MTTR.

Pipeline GitHub Actions — React App

"Cada músico de la orquesta sigue la partitura — este es el YAML que dirige el pipeline React, como Willie dirigía a sus músicos."

— El arreglo de Colón ↔ el workflow de GitHub Actions
// 7 Jobs — La Orquesta
.github/workflows/pipeline.yml
overview
# ────────────────────────────────────────────────────
#  CI/CD Pipeline — React App con GitHub Actions
#  ♪ Dirigido como la orquesta de Willie Colón
# ────────────────────────────────────────────────────

name: React CI/CD Pipeline

on:
  push:
    branches: [main, develop]
  pull_request:
    branches: [main, develop]

concurrency:
  group: ${'{'} github.workflow {'}'}-${'{'} github.ref {'}'}
  cancel-in-progress: true

env:
  NODE_VERSION: '20.x'
  BUILD_DIR: 'dist'

# ── Flujo ♪ ──────────────────────────────────────
#
#   install (🥁 base rítmica)
#      ├── lint ──┐
#      ├── test ──┴──► build ──► security
#      └── security       ├── deploy-staging (develop)
#                         └── deploy-prod    (main)
#
jobs:
  install # 🥁 La clave — todo parte aquí
  lint    # 🎸 needs: install
  test    # 🎵 needs: install
  build   # 🎼 needs: [lint, test]
  security # 🛡️ needs: install
  deploy-staging # 🚀 needs: [build, security]
  deploy-production # 🎉 needs: [build, security]

  install: # 🥁 Base rítmica — todo depende de esto
    name: 📦 Install Dependencies
    runs-on: ubuntu-latest
    steps:
      - name: Checkout
        uses: actions/checkout@v4
      - name: Configurar Node.js
        uses: actions/setup-node@v4
        with:
          node-version: ${'{'} env.NODE_VERSION {'}'}
          cache: 'npm'
      - name: npm ci
        run: npm ci
                # Más determinista que npm install en CI
      - name: Cachear node_modules
        uses: actions/cache@v4
        with:
          path: node_modules
          key: node-modules-${'{'} runner.os {'}'}-${'{'} hashFiles('package-lock.json') {'}'}

  lint: # 🎸 Afinación — ESLint + Prettier
    name: 🔍 Lint & Format
    runs-on: ubuntu-latest
    needs: install
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with: { node-version: ${'{'} env.NODE_VERSION {'}'} }
      - name: Restaurar caché
        uses: actions/cache@v4
        with:
          path: node_modules
          key: node-modules-${'{'} runner.os {'}'}-${'{'} hashFiles('package-lock.json') {'}'}
      - name: ESLint
        run: npm run lint
                # "eslint src --ext .js,.jsx,.ts,.tsx --max-warnings 0"
      - name: Prettier check
        run: npm run format:check

  test: # 🎵 El ensayo — cobertura mínima 80%
    name: 🧪 Unit Tests & Coverage
    runs-on: ubuntu-latest
    needs: install
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with: { node-version: ${'{'} env.NODE_VERSION {'}'} }
      - name: Restaurar caché
        uses: actions/cache@v4
        with:
          path: node_modules
          key: node-modules-${'{'} runner.os {'}'}-${'{'} hashFiles('package-lock.json') {'}'}
      - name: Tests + cobertura
        run: npm run test:coverage
        env: { CI: true }
      - uses: actions/upload-artifact@v4
        with: { name: coverage-report, path: coverage/, retention-days: 7 }
      - name: Verificar umbral ≥ 80%
        run: |
          COVERAGE=$(node -e "const j=require('./coverage/coverage-summary.json');
            console.log(j.total.lines.pct)")
          if (( $(echo "$COVERAGE < 80" | bc -l) )); then
              echo "❌ Cobertura $COVERAGE% < 80%"; exit 1
          fi; echo "✅ $COVERAGE% — Willie aprobaría esto"

  build: # 🎼 La grabación final — Vite build
    name: 🏗️ Build
    runs-on: ubuntu-latest
    needs: [lint, test]
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with: { node-version: ${'{'} env.NODE_VERSION {'}'} }
      - name: Restaurar caché
        uses: actions/cache@v4
        with:
          path: node_modules
          key: node-modules-${'{'} runner.os {'}'}-${'{'} hashFiles('package-lock.json') {'}'}
      - name: Vite Build
        run: npm run build
        env:
          VITE_API_URL: ${'{'} secrets.VITE_API_URL {'}'}
          VITE_APP_ENV: ${'{'} github.ref == 'refs/heads/main' && 'production' || 'staging' {'}'}
      - name: Subir artefacto del build
        uses: actions/upload-artifact@v4
        with:
          name: react-build-${'{'} github.sha {'}'}
          path: ${'{'} env.BUILD_DIR {'}'}/
          retention-days: 3

  security: # 🛡️ El guardián del barrio — npm audit + Snyk
    name: 🔒 Security Audit
    runs-on: ubuntu-latest
    needs: install
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with: { node-version: ${'{'} env.NODE_VERSION {'}'} }
      - name: Restaurar caché
        uses: actions/cache@v4
        with:
          path: node_modules
          key: node-modules-${'{'} runner.os {'}'}-${'{'} hashFiles('package-lock.json') {'}'}
      - name: npm audit — El Malo del Bronx no permite vulnerabilidades HIGH
        run: npm audit --audit-level=high
      - name: Snyk SCA
        uses: snyk/actions/node@master
        continue-on-error: true
        env: { SNYK_TOKEN: ${'{'} secrets.SNYK_TOKEN {'}'} }
        with: { args: --severity-threshold=high }

  deploy-staging: # 🚀 El club del barrio — prueba antes del Madison SQ
    name: 🚀 Deploy → Staging
    runs-on: ubuntu-latest
    needs: [build, security]
    if: github.ref == 'refs/heads/develop' && github.event_name == 'push'
    environment:
      name: staging
      url: https://staging.mi-app-react.com
    steps:
      - uses: actions/checkout@v4
      - name: Descargar build
        uses: actions/download-artifact@v4
        with: { name: react-build-${'{'} github.sha {'}'}, path: dist/ }
      - uses: aws-actions/configure-aws-credentials@v4
        with:
          aws-access-key-id: ${'{'} secrets.AWS_ACCESS_KEY_ID {'}'}
          aws-secret-access-key: ${'{'} secrets.AWS_SECRET_ACCESS_KEY {'}'}
          aws-region: us-east-1
      - name: S3 sync + cache headers
        run: |
          aws s3 sync dist/ s3://${'{'} secrets.S3_BUCKET_STAGING {'}'}/ \
            --delete --cache-control "public,max-age=31536000,immutable" \
            --exclude "index.html"
          aws s3 cp dist/index.html \
            s3://${'{'} secrets.S3_BUCKET_STAGING {'}'}/index.html \
            --cache-control "no-cache,no-store,must-revalidate"
      - name: CloudFront invalidation
        run: |
          aws cloudfront create-invalidation \
            --distribution-id ${'{'} secrets.CF_DISTRIBUTION_STAGING {'}'} --paths "/*"

  deploy-production: # 🎉 El Madison Square Garden — con aprobación manual
    name: 🌐 Deploy → Production
    runs-on: ubuntu-latest
    needs: [build, security]
    if: github.ref == 'refs/heads/main' && github.event_name == 'push'
    environment:
      name: production # ← activar "required reviewers"
      url: https://mi-app-react.com
    steps:
      - uses: actions/checkout@v4
      - name: Descargar build
        uses: actions/download-artifact@v4
        with: { name: react-build-${'{'} github.sha {'}'}, path: dist/ }
      - uses: aws-actions/configure-aws-credentials@v4
        with:
          aws-access-key-id: ${'{'} secrets.AWS_ACCESS_KEY_ID {'}'}
          aws-secret-access-key: ${'{'} secrets.AWS_SECRET_ACCESS_KEY {'}'}
          aws-region: us-east-1
      - name: S3 sync + CloudFront
        run: |
          aws s3 sync dist/ s3://${'{'} secrets.S3_BUCKET_PROD {'}'}/ \
            --delete --cache-control "public,max-age=31536000,immutable" \
            --exclude "index.html"
          aws s3 cp dist/index.html \
            s3://${'{'} secrets.S3_BUCKET_PROD {'}'}/index.html \
            --cache-control "no-cache,no-store,must-revalidate"
          aws cloudfront create-invalidation \
            --distribution-id ${'{'} secrets.CF_DISTRIBUTION_PROD {'}'} --paths "/*"
      - name: 🎉 Crear Release — como un nuevo álbum de Willie
        uses: actions/create-release@v1
        env: { GITHUB_TOKEN: ${'{'} secrets.GITHUB_TOKEN {'}'} }
        with:
          tag_name: v${'{'} github.run_number {'}'}
          release_name: Release v${'{'} github.run_number {'}'} 🎺
          draft: false
          prerelease: false
